# 本地视频动态壁纸

一款面向 Windows 10 / Windows 11 64 位系统的轻量级本地视频动态壁纸工具。程序使用 Explorer 的桌面背景窗口承载视频，画面位于桌面图标下方，不使用置顶窗口模拟壁纸。

## 当前实现

- 选择并记住本地视频；首选 MP4/H.264，也允许由 libmpv 实际验证的常见本地容器。
- 每块显示器使用独立渲染进程，支持等比填充、等比适应、拉伸铺满、原尺寸居中和平铺。
- 默认静音、循环播放，优先使用 D3D11 和安全的硬件解码模式；可选择播放视频自带音频，多屏只输出一路声音。
- 窗口关闭后进入系统托盘；托盘可打开界面、开启、关闭、切换层级优先级或退出。
- 显示器热插拔、分辨率与 DPI 变化后重新适配。
- 锁屏、睡眠、显示器关闭等情况固定销毁播放器并释放资源；其他应用最大化/全屏时可分别选择保持运行、暂停或停止，默认停止；恢复后按策略继续。
- 保存只读系统背景快照，但不修改系统背景设置。移除本程序窗口后，原背景自然重新显示。
- 渲染进程由 Windows Job Object 管理，主程序异常退出时不遗留播放器进程。
- 可动态选择“较低/最高”壁纸层级；只在安全壁纸层内部调整顺序。
- 不连接网络，不读取在线媒体，不加载用户 mpv 配置、外部脚本、字幕或外部引用。

## 系统要求

- Windows 10 1607 或更高版本，或 Windows 11，64 位。
- Python 3.12 或更高版本（源码运行）。
- PySide6 6.8–6.x。
- Windows x64 版 libmpv。推荐 mpv 0.38 或更新版本，构建必须包含 FFmpeg/H.264、D3D11 和 `vo=gpu`。

本仓库不附带第三方播放器二进制。把可信来源的 `mpv-2.dll` 或 `libmpv-2.dll` 及其依赖 DLL 放入 [vendor/mpv/](vendor/mpv/)，具体要求见 [vendor/mpv/README.md](vendor/mpv/README.md)。

> `mpv.exe` 不能替代 libmpv DLL。程序只接受 64 位 PE DLL，并在真正选择视频时校验解码与首帧输出。

## 源码运行

```powershell
cd D:\path\to\dynamic-wallpaper
python -m pip install -e .
python -m dynamic_wallpaper --diagnose
python -m dynamic_wallpaper
```

也可显式指定播放器运行库：

```powershell
python -m dynamic_wallpaper --mpv-library D:\mpv\mpv-2.dll
```

或设置 `DYNAMIC_WALLPAPER_MPV_DLL` 环境变量。显式路径无效时，程序会报错而不是从不受控目录加载其他 DLL。

### 只读诊断

```powershell
python -m dynamic_wallpaper --diagnose
```

诊断会检查显示器、会话状态、桌面宿主、系统背景快照及 libmpv 初始化。它不会创建壁纸窗口，也不会修改桌面。

## 使用方法

设置窗口在普通状态保持紧凑尺寸，四边和四角不能拖拽缩放；可通过标题栏最大化，还原后回到紧凑尺寸。仍可移动、最小化，关闭后隐藏到托盘。

1. 启动程序。
2. 点击“选择视频”。只有实际解码出视频首帧后才会保存路径并启用“开启壁纸”。
3. 选择“显示方式”和是否“播放视频音频”（默认等比填充、静音）。
4. 在主界面或托盘右键菜单“层级优先级”中选择：
   - **较低**：放在同一壁纸层中其他壁纸窗口的后方。
   - **最高**：放在同一壁纸层中其他壁纸窗口的前方，但仍位于桌面图标下方。
5. 点击“开启壁纸”。所有目标屏幕准备好后才会一起显示，避免半完成状态。
6. 显示方式、音频开关、视频音量和两项自动策略可实时调整，无需重启程序；更换视频时沿用设置。
7. 关闭主窗口会隐藏到托盘；托盘右键“暂停播放”可保留当前画面并停止声音，暂停后该项变为“继续播放”。
8. 使用“关闭壁纸”释放全部播放器；使用托盘“退出程序”完成相同清理后退出。

手动暂停是临时状态，不写入配置；更换视频或解锁恢复时仍保持手动暂停，关闭壁纸后清除。手动继续不会绕过锁屏、睡眠或屏幕覆盖等自动暂停条件。手动暂停保留播放器和当前画面，不等同于关闭并释放全部资源。

程序已运行时，再次启动只唤起原有窗口，不创建新的托盘或播放器。隐藏窗口会显示，最小化窗口会还原，原有最大化状态保持，并临时显示到前台；不设置永久置顶。若已有窗口仍在初始化或未响应，会显示提示而不是静默退出。更新程序后请先退出旧实例，再启动新版。

### 显示方式与画质

| 显示方式 | 效果 |
| --- | --- |
| 等比填充（默认） | 保持比例铺满屏幕，居中裁剪超出部分。 |
| 等比适应 | 完整显示画面、保持比例；左右留白使用对应视频边缘模糊拉伸填充，上下留白仍为黑色。 |
| 拉伸铺满 | 完整画面填满屏幕，可能发生比例变形。 |
| 原尺寸居中 | 按原始显示尺寸居中、不缩放；上下左右留白使用对应视频边缘模糊填充，超出部分居中裁剪。 |
| 平铺 | 按原始显示尺寸从屏幕左上角重复同一画面，裁剪边缘超出部分。 |

每屏独立适配。平铺使用 GPU 重复采样同一份解码画面，不为每个小格创建播放器。原始显示尺寸包含视频的旋转和像素宽高比信息。

程序直接播放原视频，不压缩、不转码、不生成低清副本，也不修改源文件。缩放和屏幕分辨率仍会影响最终显示的细节；低分辨率视频放大不会增加真实细节。需要避免缩放时选择“原尺寸居中”。

### 视频音频

勾选“播放视频音频”后，只播放视频文件内的音轨；没有音轨的视频仍正常显示。“视频音量”滑块范围为 0～100%，默认 100%，只调整壁纸播放器，不修改 Windows 总音量；关闭音频开关时仍可预设音量，下一次启用或音频交接时沿用。音量和开关会保存。Windows 音量混合器的设置也会共同影响最终音量。

音频开关使用短淡入/淡出。关闭时先淡出并等待少量输出缓冲，再静音；已经打开的音轨和输出通道不因每次开关立即拆除，避免设备反复开关引起短促异响。首次未启用音频的播放器仍不选择音轨；启用后再关闭会保留静音通道及其解码资源，直到播放器停止或退出时释放。物理设备端是否仍有爆音需要在实际喇叭/耳机上确认。

### 自动播放策略

单页设置窗口提供“其他应用程序最大化时”和“其他应用程序全屏时”两项，分别支持：

| 选项 | 行为 |
| --- | --- |
| 保持运行 | 对应屏幕继续播放和解码，音频仍受开关及音量设置控制。 |
| 暂停 | 保留该屏播放器和当前帧，停止该屏播放及音频输出，不释放全部内存/GPU 资源。 |
| 停止（释放内存）（默认） | 销毁该屏播放器、移除播放层并显示系统背景；条件解除后按附近保存位置重建。主程序不会退出。 |

两项按显示器独立生效，同一屏幕存在多个遮挡条件时，采用“停止 > 暂停 > 保持运行”。锁屏、睡眠、显示器关闭、会话不可见或显示器状态不可用时始终停止释放，不提供专项设置。自动恢复不解除手动暂停，用户主动关闭后也不会自动重启。

最大化与全屏通过窗口状态、边框及覆盖区域综合判定；自动隐藏任务栏的普通最大化窗口不会只因尺寸等于屏幕而改判为全屏。无边框或特殊窗口仍需在目标应用上做兼容性验证。

多显示器只输出一路音频：优先使用未暂停、未停止的主屏播放器，主屏暂停时交给其他仍在播放的屏幕，主屏恢复后再交回，交接前应用保存的壁纸音量。交接会等待旧播放器确认静音或退出，避免声音叠加；由于各屏不逐帧同步，交接时可能出现短暂停顿或播放位置跳变。所有屏幕都暂停/停止、锁屏、睡眠或用户关闭壁纸时声音停止；选择“保持运行”的屏幕仍可按音频设置输出声音。

不同第三方壁纸软件可能使用其他桌面层或持续重排自己的窗口，层级兼容性不能对任意软件保证。程序不会为抢占层级而隐藏、销毁 Explorer 或第三方窗口。

## 配置和日志

数据保存在当前用户目录：

```text
%LOCALAPPDATA%\LocalDynamicWallpaper\
├── config.json        # 用户设置：视频路径、层级、显示方式、音频、音量、最大化/全屏策略
├── session.json       # 壁纸会话记录：开启前的系统背景快照
└── logs\              # 1 MiB × 3 的轮转日志
```

配置保存最后一次通过验证的视频路径、层级、显示方式、音频开关、音量及最大化/全屏策略。更换视频时沿用设置，下次启动恢复；旧版配置默认使用等比填充、静音、100% 音量及两项“停止”策略。启动时会验证上次视频，但不会自动开启壁纸或播放声音。

### config.json：用户设置

以下为示例，路径需替换为自己的本地视频：

```json
{
  "version": 3,
  "last_video": "D:\\Videos\\wallpaper.mp4",
  "priority": "low",
  "display_mode": "cover",
  "audio_enabled": false,
  "volume": 100,
  "maximized_action": "stop",
  "fullscreen_action": "stop"
}
```

| 字段 | 类型 / 取值 | 对应含义 |
| --- | --- | --- |
| `version` | 整数，当前写入 `3` | 配置文件结构版本，不是应用或播放器版本。 |
| `last_video` | 字符串或 `null` | 最后选择并通过校验的本地视频完整路径；`null` 表示尚未选择视频。JSON 中的 Windows 路径反斜杠需写成 `\\`。 |
| `priority` | `"low"` / `"high"` | 主界面和托盘的“层级优先级”：`low`＝较低，`high`＝最高。仅调整安全壁纸层内的顺序，不是 CPU/进程优先级。 |
| `display_mode` | 下表中的字符串 | 主界面的“显示方式”，默认 `"cover"`。 |
| `audio_enabled` | 布尔值 `true` / `false` | “播放视频音频”开关，默认 `false`（静音）。必须是 JSON 布尔值，不能写成字符串 `"true"` 或 `"false"`。 |
| `volume` | 整数 `0`～`100` | “视频音量”，默认 `100`；只调整壁纸，不修改系统总音量。音频关闭时保存为预设值。 |
| `maximized_action` | `"keep"` / `"pause"` / `"stop"` | “其他应用程序最大化时”：保持运行、暂停、停止（释放内存），默认 `"stop"`。 |
| `fullscreen_action` | `"keep"` / `"pause"` / `"stop"` | “其他应用程序全屏时”，取值含义同上，默认 `"stop"`。两项按屏幕独立生效。 |

`display_mode` 取值对应如下：

| 值 | 界面选项 | 显示效果 |
| --- | --- | --- |
| `"cover"` | 等比填充 | 保持比例铺满屏幕，居中裁剪超出部分。 |
| `"contain"` | 等比适应 | 完整显示主画面，左右留白由对应视频边缘模糊填充；上下留白为黑色。 |
| `"stretch"` | 拉伸铺满 | 完整画面拉伸到屏幕大小，可能改变比例。 |
| `"center"` | 原尺寸居中 | 主画面不缩放，上下左右留白模糊填充，超出屏幕的部分居中裁剪。 |
| `"tile"` | 平铺 | 按原始显示尺寸重复同一画面，裁剪边缘超出部分。 |

这里只保存设置，不保存“壁纸是否开启”、手动暂停状态或视频播放进度。建议通过界面调整；如需手动编辑，请先退出程序，避免运行中的设置保存覆盖修改。

### session.json：壁纸会话与系统背景快照

点击“开启壁纸”时创建，正常关闭壁纸或退出并完成资源清理后删除。异常退出时可能遗留，下次启动会检查该记录。它不是用户设置文件，也不是视频播放列表。

```json
{
  "version": 1,
  "changes_system_wallpaper": false,
  "snapshot": {
    "captured_at": "2026-11-15T08:00:00+00:00",
    "monitors": [
      {
        "device": "\\\\?\\DISPLAY#EXAMPLE",
        "wallpaper": "C:\\Pictures\\desktop.jpg"
      }
    ],
    "color": 0,
    "position": 4,
    "status": 1,
    "slideshow": {
      "sources": [],
      "options": 0,
      "interval_ms": 600000
    }
  }
}
```

上例仅演示结构，设备标识、路径和背景设置以 Windows 实际返回的信息为准。

| 字段 | 类型 / 单位 | 对应含义 |
| --- | --- | --- |
| `version` | 整数，当前写入 `1` | 会话记录结构版本，独立于上面的配置版本。 |
| `changes_system_wallpaper` | 布尔值，当前固定为 `false` | 标明本程序没有修改 Windows 的系统背景设置。遗留记录只有明确包含 `false` 时才会被安全清理；不要手动改动此字段。 |
| `snapshot` | 对象 | 开启壁纸前通过 Windows 桌面背景接口读取的只读快照。 |
| `snapshot.captured_at` | ISO 8601 时间字符串 | 快照时间，使用 UTC；示例末尾的 `+00:00` 表示 UTC 时区。 |
| `snapshot.monitors` | 对象数组 | 系统背景接口返回的各显示器背景信息。 |
| `snapshot.monitors[].device` | 字符串 | Windows 桌面背景 API 的显示器设备路径/标识，不是显示器名称，也不一定等于 `DISPLAY1`。 |
| `snapshot.monitors[].wallpaper` | 字符串 | 该显示器原有系统壁纸的图片路径；可能为空字符串。不是本程序选择的视频路径。 |
| `snapshot.color` | 整数，Windows `COLORREF` | 原系统背景颜色，编码为 `0x00BBGGRR`；`0`＝黑色，`16777215`＝白色。 |
| `snapshot.position` | 整数，见下文 | 原系统壁纸的布局方式，不是本程序的 `display_mode`。 |
| `snapshot.status` | 整数，位标志 | 系统背景/幻灯片状态：`1`＝已启用，`2`＝幻灯片模式，`4`＝因远程会话被禁用；多个标志可相加，例如 `3` 表示启用且处于幻灯片模式。 |
| `snapshot.slideshow` | 对象 | 原系统壁纸的幻灯片设置，即使当前未使用幻灯片也会记录。 |
| `snapshot.slideshow.sources` | 字符串数组 | 幻灯片来源的路径或 Shell 解析名称；可能包含文件夹，不一定是单张图片。未设置时可为空数组。 |
| `snapshot.slideshow.options` | 整数，位标志 | 幻灯片选项：`0`＝默认顺序，`1`＝随机排列。 |
| `snapshot.slideshow.interval_ms` | 整数，毫秒 | 系统幻灯片切换间隔；例如 `600000`＝10 分钟。 |

`snapshot.position`：`0`＝居中、`1`＝平铺、`2`＝拉伸、`3`＝适应、`4`＝填充、`5`＝跨显示器。

快照仅记录开启前的系统背景信息。播放时不把视频写入这些字段；关闭壁纸时移除播放层，让系统当前背景重新显露，不会用旧快照强行覆盖用户期间修改的背景。

## 自动测试

```powershell
python -m unittest discover -s tests -v
```

测试覆盖状态机、原子切换、异常回滚、暂停原因、多显示器模型、显示方式、配置、子进程超时、Job Object、界面按钮和音频交接确认。

安装了 libmpv 的 Windows 环境还可运行隐藏窗口原生测试，检查 D3D11 平铺像素、旋转、尺寸变化、真实子窗口和视频内嵌音频开关：

```powershell
$env:DYNAMIC_WALLPAPER_NATIVE_TESTS = "1"
python -m unittest discover -s tests -v
Remove-Item Env:DYNAMIC_WALLPAPER_NATIVE_TESTS
```

原生测试使用临时生成的无压缩测试视频和静音 PCM 音轨，不修改 Explorer 桌面。真实桌面交互、多屏听感和长时间行为仍需按验收文档在目标机器上验证。

## 打包

打包前必须先把 libmpv 及依赖放入 `vendor/mpv`：

```powershell
python -m pip install -e ".[build]"
python tools\build.py
```

输出位于 [dist/LocalDynamicWallpaper/](dist/LocalDynamicWallpaper/)，采用目录模式。请运行目录中的 [LocalDynamicWallpaper.exe](dist/LocalDynamicWallpaper/LocalDynamicWallpaper.exe)，分发时必须复制整个目录，包括 [_internal/](dist/LocalDynamicWallpaper/_internal/) 和 [LocalDynamicWallpaperRenderer.exe](dist/LocalDynamicWallpaper/LocalDynamicWallpaperRenderer.exe)。后者是主程序的管道子进程助手，不作为壁纸程序单独运行。

构建会清理 PyInstaller 缓存并覆盖旧的生成目录，自动补齐当前 Python 环境的原生依赖，兼容 Conda 将 libffi 等标准库依赖放在 `Library/bin` 的布局。不要从网上下载同名 DLL 或混用其他 Python 版本的 DLL。

构建完成后，脚本会从临时目录运行打包助手的 `--diagnose`，移除 Python/Conda 搜索路径及外部 mpv DLL 配置，检查独立启动和包内 libmpv 加载。只有自检通过才返回成功；此检查不创建壁纸窗口，也不修改桌面。libmpv 缺失、DLL 依赖缺失或自检失败时，构建命令返回非零退出码。

发布时必须审查所选 mpv/FFmpeg 构建的 GPL/LGPL 条款，并随产品提供相应许可证、版权信息及适用的源码提供方式。

## 已知技术边界

- Explorer 的 `Progman/WorkerW` 桌面结构没有稳定的公开视频壁纸 API。程序在挂载前验证窗口类别、进程、父子关系和尺寸；不兼容时安全失败。
- 多显示器各自解码同一视频，不承诺逐帧同步，也不承诺与单屏相同的资源占用。
- 硬件解码是优先策略；视频参数或驱动不支持时，libmpv 可能回退到软件解码。
- “最高/较低”只描述本程序在可控安全壁纸层中的相对 Z 序。
- 项目不包含开机启动、在线播放、播放列表、图片/GIF、音频编辑、滤镜或每屏独立视频等范围外功能。
